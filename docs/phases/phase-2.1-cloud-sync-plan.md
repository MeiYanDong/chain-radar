# Phase 2.1 Plan：云服务器同步与常驻运行

> 维护规则：本文档是 Phase 2.1 的详细产品计划。它可以由 Agent 更新，但要保持产品视角，避免写成命令清单。

## 1. 阶段目标

让 Pot Monitor 在云服务器上稳定运行。

完成后，用户不需要一直开着本机终端，也能持续收到关键 P&L 变化提醒。

## 2. 用户价值

用户真正想要的是：

- 不用守着电脑。
- 不用一直刷新 Virtuals Degen 页面。
- 有重要变化时及时知道。
- 收到提醒后能快速判断要不要打开页面继续看。

## 3. 当前范围

本阶段只做稳定运行相关工作：

- 同步当前项目到云服务器。
- 配好运行所需环境。
- 让 Pot Monitor 可以长期运行。
- 保证飞书提醒可以正常发送。
- 保留网页查看能力。

## 4. 暂不处理

本阶段不做：

- 不重新设计提醒阈值。
- 不恢复大户成本分析的实时扫描。
- 不增加自动交易。
- 不扩展复杂新页面。
- 不重构成大型平台。

## 5. 成功标准

- 云服务器上 Pot Monitor 可以持续运行。
- Pot Monitor 能正常拉取 10 个 Agent 的数据。
- 飞书 webhook 配置正确。
- 程序重启或迁移旧数据库后不会重复轰炸提醒。
- 出现异常数据时不会把空值当成真实亏损提醒。
- 用户能通过网页查看当前数据；如果需要公网访问，必须由用户确认后再开放。

## 6. 风险

- 服务器环境变量缺失，导致飞书不发消息。
- 进程没有守护，终端关闭后程序停止。
- API 偶发返回不完整数据，造成误报。
- 本地和服务器数据库状态不一致。
- 部署后没有明确日志，后续排障困难。
- 小规格服务器远端构建可能打满磁盘 I/O，需要优先采用本机构建后同步产物的方式。

## 7. 与下一阶段的关系

Phase 2.1 只解决“稳定跑起来”。

提醒阈值是否合理、是否要改成动态规则、是否要根据历史波动分层，放到 Phase 2.2 处理。
